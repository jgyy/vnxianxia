# AGENTS.md: vnxianxia (repository root)

A third-person xianxia action-RPG, *The Lotus and the Blood Moon*, built entirely from code. There are 2000 main quests,
five large exterior maps plus 13 interiors, and 14 rigged characters and creatures. Every model, texture, map, story
line, voice line, music cue and HUD piece is generated by a script in this repository. The game runs in **Godot
4.7.2**. The asset generators run in **headless Blender 5.2.2** (`bpy`). Maps and story come from stdlib Python.
README.md shows the result, docs/STORY.md explains the story data, and docs/AUDIO.md covers the audio synthesis.

## Pipeline in one paragraph

`tools/world_spec.py` is the **single source of truth** for every map id, marker name, character model, NPC model,
enemy, item, quest prop, realm and alignment. It is exported to `godot/data/world.json`. The map modules in
`tools/maps/` place GLBs and markers and write `godot/scenes/maps/*.tscn`. The story in `tools/story/` is compiled and
validated by `tools/build_story.py` into `godot/data/story.json`. `tools/gen_voices.py` synthesises the voiced lines
with Piper, and `tools/gen_audio.py` synthesises the music and SFX. `blender/build_assets.py` writes every GLB under
`godot/assets/`. The terrain GLBs read their height fields from `tools/maps`, so the ground and the layouts agree.

## Generated files: never hand-edit, regenerate with the tool

| Output | Command |
|---|---|
| `godot/assets/{characters,environment,items}/*.glb` | `python blender/build_assets.py [--only a,b]` |
| `godot/ui/portraits/*.png` | `python blender/render_portraits.py` |
| `godot/ui/hud/*.png`, `hud_kit.json` | `python blender/render_hud.py` |
| `godot/ui/loading/*.jpg` | `godot --path godot --rendering-driver vulkan -s res://tests/capture_loading_art.gd` |
| `godot/data/world.json` | `python tools/world_spec.py` |
| `godot/scenes/maps/*.tscn` | `python tools/build_maps.py [map_id ...]` |
| `godot/data/story.json` (+ `docs/QUESTS.md`) | `python tools/build_story.py [--quests docs/QUESTS.md]` |
| `godot/audio/voice/*.ogg`, `manifest.json` | `python tools/gen_voices.py [--prune]` |
| `godot/audio/music/*.ogg`, `godot/audio/sfx/*.ogg` | `python tools/gen_audio.py [--only id,id]` |

Generated binaries and their Godot `.import` sidecars are committed, so CI and players do not need Blender or Piper.
Commit the `.import` files together with new assets. `.godot/`, `build/` and the textures Godot extracts from GLBs
(`godot/assets/**/*.png|*.jpg`) are gitignored.

## Toolchain setup

```bash
python3.13 -m venv .venv && . .venv/bin/activate
pip install bpy==5.2.2 numpy scipy soundfile piper-tts     # bpy 5.2.2 needs exactly Python 3.13
# Godot 4.7.2: https://github.com/godotengine/godot-builds/releases (CI puts it at ~/godot/godot)
# Piper voice models (*.onnx + *.onnx.json) from the rhasspy/piper v0.0.2 GitHub release, in ~/voices
#   (or $PIPER_VOICES). gen_voices.py re-executes itself with $PIPER_PYTHON when piper is not importable.
```

On this machine the Blender venv is `/home/user/.venv` (`. /home/user/.venv/bin/activate`), Godot is
`~/godot/godot` and the voices are in `~/voices`. The machine is shared (4 cores): run one heavy job at a time (a Blender
build, a Godot import, a walkthrough).

## CI (.github/workflows/ci.yml) and the same checks locally

```bash
python -m py_compile blender/*.py blender/xianxia/*.py tools/*.py tools/maps/*.py tools/story/*.py
python tools/validate_glb.py godot/assets
python tools/world_spec.py --check
python tools/build_maps.py && git diff --exit-code -- godot/scenes/maps
python tools/build_story.py --check
python tools/gen_voices.py --check
godot --headless --path godot --import                                  # first run: several minutes
godot --headless --path godot -s res://tests/smoke_test.gd
godot --headless --path godot -s res://tests/walkthrough_test.gd -- 1 100   # CI: 20 shards of 100 quests
```

The CI jobs are `lint` (all the Python checks above), `blender-build` (a full `build_assets.py --out build/assets` plus
`validate_glb.py` on the result), `godot-smoke-test`, `godot-walkthrough` (a 20-shard matrix) and `screenshots`
(lavapipe + xvfb, at least 12 PNGs). These tests are not in CI: `res://tests/animations_test.gd`,
`tools/zfight_glb.py` (z-fighting scan) and `res://tests/capture_world_check.gd` (marker ground check against the real
collision). Run them when you touch animations, geometry or map layouts.

## Repo-wide conventions

- **Units are metres. Blender is Z-up and a model's front faces -Y. After glTF export that is Godot +Z (Y-up).**
  Map yaw 0 means "front facing south". Every builder puts the origin at the ground centre, except items, which use
  the bottom centre.
- Collision comes from Godot import-hint suffixes on node names: `-colonly` (trimesh), `-convcolonly` (convex) and
  `-col` (visible + trimesh).
- The animation speed contract is walk 1.6, run 4.6 and sprint 6.2 m/s (sneak 1.0, crouch_walk 0.8, walk_back and
  strafes 1.0). It lives in `blender/xianxia/gait.py` and `godot/scripts/player.gd` (`AUTHORED_SPEED`). Change both
  or neither.
- Generators are deterministic, with fixed seeds. CI regenerates the maps and diffs them, and checks that
  story.json and world.json are up to date.
- A new marker, prop, item, model or enemy goes into `tools/world_spec.py` **first**. Then build what it names and
  re-export world.json.
- Bug logs live in `docs/bugfixes/*.md`, one line per defect: symptom -> cause -> fix (file:line). Read the one for
  your area before changing it, and add to it when you fix a real defect.
- `.md` files are ignored by Godot's importer and by every tool here, so `AGENTS.md` files are safe in any directory.
