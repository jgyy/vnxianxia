# Animation bug log

Numbers come from `gait.verify_clip` (blender/xianxia/gait.py), which samples the baked
clip as the game plays it (whole-frame samples, linear in between) and measures stance
foot slip against the ground moving at the authored speed.

1. Humanoid `walk`/`run` feet skate during contact (3.9 cm per stance at 1.6 m/s, run 5.5 cm at its own pace) -> legs were pure FK sine waves with no foot planting (`characters.build_actions.locomotion`) -> IK gait with ground-locked heel/ball/toe pivots, now <= 5 mm per stance (mostly < 1 mm) on every body type (blender/xianxia/characters.py:1311, blender/xianxia/gait.py:1121).
2. Walk/run cycle ground speed matched neither the game nor each other (feet implied 1.9 m/s walk, 5.4 m/s run; golem 2.5 / 7.0 m/s, while the player moves at 1.6 / 4.6) -> stride and cycle length were arbitrary angles and frame counts -> Froude-scaled cadence per leg length and stance travel = authored speed x stance time exactly (blender/xianxia/gait.py `cycle_frames`, `Gait.pivot_off`).
3. Run toes and heels sink up to 4.3 cm through the floor (golem 5.4 cm) -> FK foot pitch never checked against the ground -> IK stance on the floor plane plus a swing ground-clearance correction; now <= 0.7 cm, mostly toe-cap rounding (blender/xianxia/gait.py `Gait._clearance`).
4. The NPC run leaned the trunk ~13 deg backwards while the head pitched forward -> sign error: `qa(X, -lean * 0.4)` on hips/spine/chest, but +X pitch is forward in Poser's world-axis deltas -> torso layer with forward pelvis/spine lean and a head that holds the gaze level (blender/xianxia/gait.py `Gait.torso`).
5. NPC walk bobbed upside down: pelvis lowest at mid-stance, highest at double support -> bob `-(0.5 + 0.5 cos 2ph)` has its minimum where the legs pass each other -> pelvis height solved from the stance legs (inverted pendulum in walk, lowest in stance / ballistic in flight for run) (blender/xianxia/gait.py `Gait._pelvis`).
6. Hero `walk_back`, `strafe_l/r`, `sneak`, `crouch_walk` slid 25-45 cm per step -> authored at 0.43-0.55 m/s (stride / (duty x T)) while the runtime plays them for 1.0 / 0.8 m/s -> generated at the contract speeds (blender/xianxia/moves.py:739-830).
7. Hero `sprint` slid 6 cm per stance -> its feet travelled at 3.9 m/s against a 6.2 m/s sprint -> generated at 6.2 m/s with a 0.22 duty factor (blender/xianxia/moves.py:802).
8. Feet stopped dead at lift-off and at touchdown in the old procedural gaits (visible stutter) -> swing used a smoothstep (zero end velocity) while stance moved at stride/duty, a velocity discontinuity -> C1 Hermite swing that leaves and rejoins stance with matching position and velocity (blender/xianxia/gait.py `Gait._swings`; old `moves.gait` removed).
9. Swing foot touched down early and skated along the floor for the last 7% of each swing -> lift `sin(pi * min(1, v * 1.08))` reached zero before the foot finished travelling forward -> removed with the old stepping function (blender/xianxia/moves.py, `gait()` deleted).
10. Strafing at the contract speed would cross the legs (each foot swept +/-0.5 m around its own hip) -> a symmetric walking phase pattern was used for sideways travel -> side-shuffle: lead foot opens, trail foot closes, stance lines placed so the gap never drops below 15 cm (blender/xianxia/gait.py `Gait.__init__` strafe branch).
11. Toe tip dragged 1.6 cm forward along the floor at every push-off -> toes unbent the instant the ball of the foot lifted -> toe rocker: the tip stays planted while the ball lifts and the MTP joint keeps extending (blender/xianxia/gait.py:656 `stance_state`).
12. Toes curled down under the lifted forefoot whenever a keyed clip rocked back on the heel (run_stop, landings, the old toe-first gaits) -> `tc` (toe contact) kept the toes flat for any foot pitch, also toes-up -> toe contact only applies while the heel is up (blender/xianxia/moves.py:512).
13. `play_flute` finger taps jumped at the loop seam -> taps used `sin(t * 0.45)`, 4.58 taps per 64-frame loop -> exactly 5 taps per loop (blender/xianxia/moves.py:1954).
14. `charge_hold` tremor jumped at the loop seam -> `tremble()` frequencies were not whole cycles of the 30-frame loop -> `period` argument rounds them to whole cycles per loop (blender/xianxia/moves.py:964).
15. `run_start` handed over to `run` with the legs swapped (it ended on a right heel strike, the run cycle starts on the left one), so the 0.25 s crossfade scissored the legs through each other -> mirrored so it drives off the other foot, and its last frame (and `run_stop`'s first) are keyed from the run cycle's actual first pose (blender/xianxia/moves.py:764, `gait.pose_at`).
16. Keyed hero loops were baked on every other frame with AUTO_CLAMPED handles; the flattened end handles eased the odd frames around the seam (e.g. `charge_hold` seam kink 0.42 deg) -> loops are baked on every frame (blender/xianxia/moves.py:543).
17. `render_animation_sheet.py --blend` rendered stale animations -> it re-ran `build_player_actions` on the cached scene, creating `*.001` duplicates while the lookup by name found the old actions -> cached scenes are used as-is (blender/render_animation_sheet.py:87).
